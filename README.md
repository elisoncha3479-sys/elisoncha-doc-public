# Elisoncha Doc

> Type: web-service

Команда виртуальных врачей в Telegram, которая собирает медицинскую
картину человека за годы и объясняет её по-человечески. Главврач читает
входящий документ (фото/скан/выписку), раздаёт его профильным
специалистам — кардиолог, нефролог, эндокринолог, лаборант и др., —
каждый смотрит своим глазом, затем главврач сводит мнения, ищет
противоречия, сверяет с историей и присылает тёплое письмо с
расшифровкой «по-простому».

**Это не замена врача.** Система помогает видеть картину и не терять
нить — но решения о лечении принимает живой доктор. При тревожных
симптомах звоните в скорую.

## What

- Приём документов в Telegram: фото и сканы (JPG/PNG/HEIC), PDF,
  Word (`.docx`) и `.odt`. Для фото/сканов — OCR, для PDF/`.docx`/`.odt` —
  прямое чтение текста. Неизвестный формат не роняет разбор: бот
  вежливо подскажет, в каком виде прислать.
- Охранник на входе: проверяет, что документ принадлежит пациенту
  (по ФИО), и переспрашивает, если не уверен — чужие документы не
  попадают в карту.
- Мультиагентный разбор: главврач → специалисты → синтез →
  сверка с историей лекарств → PDF-отчёт человеческим языком.
- Файловая память (по папке на специалиста), а не вектор-база —
  читается глазами, переживает рестарты.
- Честность на сбоях: неудачный разбор помечается и НЕ отравляет
  долгую память.

## Setup

```bash
cd bot
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env      # заполнить ключи
```

Личность пациента можно задать двумя способами:

- **Интерактивный онбординг (проще).** Напишите боту `/onboarding` —
  он сам расспросит вас (имя, обращение, дата рождения, город и пара
  деталей) одним сообщением и соберёт профиль. Ничего в `.env`
  прописывать не нужно.
- **Через `.env` (вручную).** Переменные `PATIENT_FULL_NAME`,
  `PATIENT_ADDRESS_NAME`, `PATIENT_DOB`, `PATIENT_CITY`. Удобно для
  автоматического разворачивания.

Оставите пусто и не пройдёте онбординг — бот общается тепло, но без
имени. Никаких персональных данных в коде нет.

## Run

Локально:

```bash
cd bot && source venv/bin/activate
python -u main.py
```

В Docker (рекомендуется для прода):

```bash
docker compose up -d --build
docker compose ps
```

## Test

```bash
cd bot && source venv/bin/activate
pip install -r requirements-dev.txt
pytest -q
```

Ожидается: все тесты зелёные. Данные пациента в тестах —
вымышленные, реальных людей нет.

## Массовая загрузка базы (bulk import)

Залить разом большую папку личных документов (PDF/фото/сканы,
вложенные подпапки — ок) в память специалистов тем же конвейером,
что и Telegram, но **без** доставки PDF и **без** сообщений в чат.

Папка задаётся переменной `PATIENT_INBOX_DIR` (нейтральный путь, не
зашит на конкретного человека; дефолт — `patient_inbox/` рядом с
проектом). Папка и манифест в git **не попадают** (`.gitignore`).

```bash
cd bot && source venv/bin/activate
# пробный прогон пачкой из 3 файлов:
PATIENT_INBOX_DIR=/путь/к/папке python bulk_import.py --limit 3
# полный прогон:
PATIENT_INBOX_DIR=/путь/к/папке python bulk_import.py
```

**Модель и стоимость.** По умолчанию bulk-загрузчик идёт на
**Haiku 4.5** — это в ~3 раза дешевле Sonnet и хватает по качеству
для разбора текстовых медицинских документов. Интерактивный
Telegram-путь этим файлом не затрагивается — там по-прежнему Sonnet
для лучшего качества врачебных ответов.

Честная оценка стоимости bulk: **~$0.20 на документ** (с учётом
длинного output на `profile_refresher`; не путать с «paper rate»
Haiku, который занижает реальный расход в пайплайне с большим
выводом). Безопасная прикидка перед прогоном — `~$0.20 × N файлов`.

Если для конкретного прогона нужен Sonnet (например, документы
неоднозначные, важна максимальная точность) — переопредели
переменную **до** запуска, и наш `setdefault` уступит:

```bash
# Локально:
AGENTS_MODEL=claude-sonnet-4-6 HISTORICAL_CHECK_MODEL=claude-sonnet-4-6 \
PROFILE_REFRESHER_MODEL=claude-sonnet-4-6 python bulk_import.py …

# На ВПС в контейнере:
docker exec -e AGENTS_MODEL=claude-sonnet-4-6 \
            -e HISTORICAL_CHECK_MODEL=claude-sonnet-4-6 \
            -e PROFILE_REFRESHER_MODEL=claude-sonnet-4-6 \
            doc-by-elisoncha-bot-1 python bot/bulk_import.py …
```

Свойства:

- **Идемпотентность / возобновление.** Обработанные файлы пишутся в
  манифест `.bulk_import_done.json`; повторный запуск продолжает с
  места обрыва, ничего не дублируя.
- **Сырьё не теряется.** По умолчанию исходники не удаляются. Флаг
  `--delete-after` удаляет файл **только после успешного** разбора;
  при ошибке файл остаётся.
- **Без спама в чат.** Запись в память идёт через ту же общую
  функцию, что у Telegram (`persist`), но `app=None` и
  `run_reconcile=False` — никаких уведомлений.
- **Пачками.** `--limit N` ограничивает число файлов за запуск
  (полный прогон 50–80 документов через многоагент = часы и
  заметный расход API; гнать пачками).

## Бэкап личных данных (третье место хранения)

Код живёт в трёх местах (компьютер / GitHub / VPS), а личные данные
(персона, память специалистов, медкарта) по умолчанию — только на
VPS. Чтобы данные тоже были в трёх местах, есть отдельный
**приватный** репозиторий-карман и два env-нейтральных скрипта (без
чьих-либо данных внутри):

```bash
# положить «карту здоровья» в приватный карман:
BACKUP_REMOTE=git@github.com:you/your-data.git \
CONTAINER=<имя-контейнера> ./backup-data.sh

# достать обратно (после потери VPS / пересоздания контейнера):
BACKUP_REMOTE=git@github.com:you/your-data.git \
CONTAINER=<имя-контейнера> ./restore-data.sh
```

Данные внутри контейнера под root → скрипты вынимают их через
`docker cp`, коммитят с датой и пушат. Карман **никогда не делается
публичным**. Личные данные в публичный репозиторий кода не попадают.

## Deploy

Свой VPS, через Docker. Адрес сервера в репозитории не хранится —
задаётся переменными окружения:

```bash
VPS_HOST=user@your-server VPS_PATH=/opt/elisoncha-doc ./deploy.sh
```

Скрипт пушит в git, на сервере делает `git pull` и
`docker compose up -d --build`, затем показывает логи.

## How to verify

1. `pytest -q` в `bot/` — все тесты зелёные.
2. `docker compose up -d --build`, затем `docker compose ps` —
   контейнер `healthy`.
3. Написать боту `/start` — приходит тёплое приветствие.
4. Прислать фото анализа своего профиля — приходит PDF-разбор
   человеческим языком.
5. Прислать чужой документ — охранник переспрашивает двумя кнопками,
   в карту не пишет.
6. Прислать `.odt`/`.docx` — текст читается напрямую, разбор идёт.
   Прислать неподдерживаемый формат (например `.rtf`) — бот вежливо
   просит прислать как фото/PDF/.docx, без «что-то пошло не так».
7. Массовая загрузка: `python bulk_import.py --limit 2` на тестовой
   папке — в логе по каждому файлу строка, исходники на месте,
   повторный запуск пропускает уже обработанное.

## Known limitations

- Разбор анализов близких (не основного пациента) пока не делается.
- Качество OCR зависит от того, прислали «как файл» или «как фото»
  (сжатие Telegram). Лучше — «как файл».

## Architecture

```
Telegram → main.py (хэндлеры, охранник на входе)
        → agents.py (главврач: роутинг по специалистам)
        → специалисты (agents/*.md, динамический реестр)
        → синтез + сверка лекарств с историей
        → report_renderer.py → PDF в чат
        → файловая память: specialists/<врач>/ (per-doc + profile.md)
        → history/MEDICAL_HISTORY.md (мастер-вид, регенерация)
```

Запись в память вынесена в `persist.py` — единый источник правды,
который зовут И Telegram-поток (`main.py`), И массовый загрузчик
(`bulk_import.py`). Загрузчик идёт тем же конвейером
(OCR → агенты → сверка → память), но без доставки в чат.

Реестр специалистов — динамический: новый `agents/<slug>.md` с
корректным frontmatter подхватывается без правки кода.
