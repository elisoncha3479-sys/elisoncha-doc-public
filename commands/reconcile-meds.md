# reconcile-meds — команда сверки лекарственной схемы

## Назначение

Сводит разделы 4 «ЛЕКАРСТВА ПО МОЕЙ ОБЛАСТИ» из всех 8 `specialists/<spec>/profile.md` в единый срез, выявляет:

- **противоречия** (один препарат — разные дозы / названия / статус «актуально vs отменён» у разных специалистов);
- **consensus-сигналы для пересмотра** (≥2 специалиста независимо помечают «обсудить очно / пересмотреть»);
- **открытые вопросы по терапии** (препараты «не назначены, но обсуждаются», статус неподтверждён);
- **известные лекарственные взаимодействия** в текущей схеме (информационно, не назначение);
- **запреты** (классы препаратов, явно запрещённые ≥1 специалистом по полиморбидному фону).

Это **команда-утилита**, не самостоятельный агент. Не имеет своего постоянного контекста, не общается с пациенткой, не пишет в `MEDICAL_HISTORY.md` и не правит `profile.md`. Вызывается:

- **chief'ом** — после `refresh-profile` у кардиолога/нефролога/эндокринолога/гематолога (любой смены терапии); перед регенерацией `MEDICAL_HISTORY.md`; раз в месяц планово; по явному запросу;
- **специалистом** — никогда напрямую (не его зона; специалист видит только свою область, reconcile — кросс-областной срез).

Отчёты не перезаписывают друг друга — копятся как хронологический ряд в `reports/reconciliation_<YYYY-MM-DD>.md`. Это даёт диф «что добавилось/убавилось/поменялось в схеме» между прогонами.

## Когда запускать

- После любого `refresh-profile` у специалистов с активной фармакотерапией (кардиолог, нефролог, эндокринолог, гематолог, гастроэнтеролог)
- Перед тем как chief регенерирует `history/MEDICAL_HISTORY.md`
- Перед очным визитом к врачу — чтобы пациентка пришла со сводным листом терапии, а не с восемью разными
- Раз в месяц планово (триггер: 1-е число)
- При явном запросе

## Входные параметры

Команда без параметров. Всегда обходит все 8 `specialists/<spec>/profile.md`.

| Опция | Тип | Назначение |
|-------|-----|------------|
| `--diff-with <YYYY-MM-DD>` | дата прошлого reconcile | дополнительно собрать раздел «Что изменилось с <дата>» |

## Источники данных

1. **8 `specialists/<spec>/profile.md`** — раздел 4 «ЛЕКАРСТВА ПО МОЕЙ ОБЛАСТИ» (таблица препаратов + блок «Что влияет на терапию из других областей»). Это **единственный** источник.
2. **Шапки profile.md** — поле «Последнее обновление» (для пометки «свежесть среза» и валидации, что не сводим устаревшее).
3. **Не используются:** per-doc .md (уровень `refresh-profile`), `history/MEDICAL_HISTORY.md` (mater-view, чтобы не зацикливать), `questions/pending.md` (другая очередь).

## Алгоритм

### 1. Сбор сырых данных

Для каждого `specialists/<spec>/profile.md`:

- Извлечь из шапки `Последнее обновление` (для footer'а отчёта).
- Извлечь раздел 4 целиком: таблица препаратов + текстовый блок «Что влияет на терапию...».
- Из таблицы — каждую строку как кортеж: `(препарат, доза, цель, замечание, специалист)`.
  - Если поле «Доза» = `—` — препарат явно отмечен как «не назначен» (это полезный факт, не пропускать).
  - Если в замечании есть слова «отменён», «закрыт», «исторический», «заменён» — пометить статус `historical`.
  - Если в замечании есть слова «обсудить», «пересмотреть», «под пересмотром», «открытый вопрос», `⚠️` — пометить `signal_review`.

### 2. Канонизация имён препаратов

Один и тот же препарат у разных специалистов часто пишется по-разному:

- `Престариум` ↔ `Престариум (периндоприл)` ↔ `периндоприл` → канонический ключ `периндоприл`.
- `Предуктал ОД` ↔ `Триметазидин (Предуктал ОД)` → `триметазидин`.
- `ТромбоАсс` ↔ `Тромбо АСС` ↔ `ТромбоАСС` → `ацетилсалициловая кислота`.
- `Прадакса` ↔ `Дабигатран (прадакса)` → `дабигатран`.
- `УДХК` ↔ `урсодезоксихолевая кислота` → `урсодезоксихолевая кислота`.
- `ИПП` ↔ `омепразол` ↔ `пантопразол` → каждый в свой ключ, но в группе `proton-pump-inhibitors` (для группового анализа).

Канонизация — по МНН (международному непатентованному наименованию). Торговое название хранится отдельно как «как видит специалист».

### 3. Группировка

Сгруппировать кортежи по каноническому имени препарата. Получить для каждого МНН:

- список специалистов, которые упоминают;
- набор доз/режимов от каждого;
- статус (`active` / `historical` / `not-prescribed` / `signal_review`);
- цели (показания) от каждого.

### 4. Анализ

Для каждой группы (один МНН):

- **Противоречие**, если статус `active` у всех, но дозы/режимы расходятся НЕ из-за разных трактовок одного назначения. Не считать противоречием:
  - один пишет полное название, другой МНН;
  - один пишет «35 мг × 2», другой «80 мг × 1» И в замечании явно отмечен переход (как у триметазидина 10.04.2026 — это разные эпохи, не разногласие).
- **Consensus-сигнал**, если ≥2 специалиста имеют флаг `signal_review` по одному МНН с похожим содержанием.
- **Историческое**, если статус `historical` у всех.
- **Открытый вопрос**, если ≥1 специалист обсуждает препарат, но статус `not-prescribed` (например, нитрофурантоин, УДХК).

### 5. Лекарственные взаимодействия

Для пар препаратов из активной схемы — пройти по справочно известным значимым взаимодействиям:

- Учитывать только пары, для которых есть **фактическая** клиническая значимость (не «теоретически возможно при предельных дозах»).
- Источник — общедоступные справочники фармакологии (Stockley's, RxList, EMA SmPC). При отсутствии 100%-уверенности — пометить `требует уточнения у клинического фармаколога`.
- Если взаимодействие УЖЕ отражено в чьём-то profile.md (например, клопидогрел + омепразол — кардиолог пишет про CYP2C19) — указать «уже отражено в `<spec>/profile.md`» и не дублировать как новое открытие.

### 6. Сборка запретов

Просканировать все 8 разделов 4 на предмет явных запретов классов:

- НПВС системно (нефролог, гастроэнтеролог, ортопед, эндокринолог)
- кортикостероиды в зону X (ортопед — фиброма ахилла)
- и т.п.

Группировать по классу/препарату, перечислять всех запрещающих.

### 7. Запись отчёта

Сложить отчёт в `reports/reconciliation_<YYYY-MM-DD>.md` по шаблону ниже. Если файл с такой датой уже есть — добавить суффикс `_HHMM`.

## Жёсткие правила

1. **Источник правды — только `profile.md`.** Per-doc .md и `MEDICAL_HISTORY.md` не читать. Это уровни других команд.
2. **Канонизация по МНН.** Торговые названия — отдельной колонкой. Без МНН-ключа невозможно ловить дубли «Престариум» vs «периндоприл».
3. **Не считать противоречием смену эпох.** Если в замечании явно зафиксирован переход «было X → стало Y с <дата>», и оба специалиста описывают разные срезы по времени — это согласованность, а не разногласие. Поднимать только реальные расхождения «здесь и сейчас».
4. **Consensus-сигнал требует ≥2 специалистов.** Один специалист с пометкой «обсудить» — это его внутренняя зона ответственности, не повод для cross-cutting сигнала. Двое и более — да.
5. **Лекарственные взаимодействия — только справочно известные, значимые.** Не выдумывать на основе «теоретически возможно». При сомнениях — `требует уточнения у клинического фармаколога` (это валидный исход, не отсутствие ответа).
6. **Не назначать, не отменять, не менять дозы.** Любая формулировка в отчёте — «обсудить очно», «уточнить у врача», «рассмотреть на следующем визите». Никогда «отменить» или «начать».
7. **Не перезаписывать прошлый отчёт.** Каждый прогон — новый файл `reconciliation_<YYYY-MM-DD>.md`. История срезов терапии — самостоятельная ценность.
8. **Если противоречий нет — явно это указывать.** Пустой раздел 3 без подписи легко читается как «не проверено». Писать «Противоречий не выявлено. Источники согласованы.»
9. **Уважать иерархию очного врача.** Reconciliation готовит сводный лист для разговора с лечащим врачом, а не подменяет его. Финальная фраза каждого consensus-сигнала и каждого взаимодействия — «обсудить с <такой-то специальностью> очно».
10. **Свежесть данных.** В footer'е отчёта — таблица «refresh-profile свежесть» по 8 специалистам. Если у кого-то profile.md старше 30 дней — поднять флажок «требуется refresh у <spec>» в начале отчёта.

## Что НЕ делает reconcile-meds

- Не правит `profile.md` ни у кого
- Не пишет в `history/MEDICAL_HISTORY.md`
- Не пишет в `questions/pending.md` (формат другой; pending — OCR/документные вопросы, reconcile — клинические сигналы; если из reconcile появится формат «клинический Q», его кладёт chief, не команда)
- Не пишет пациентке (тон отчёта — для команды и для лечащего врача, не для мамы; перевод в человеческий тон делает chief в weekly/monthly digest)
- Не назначает, не отменяет, не корректирует дозы
- Не валидирует OCR (это `agents/ocr-validator.md`)
- Не выполняет `refresh-profile` (это отдельная команда; если нашли устаревший profile.md — поднимаем флажок, но обновляет его именно `refresh-profile`)

## Формат отчёта о выполнении

После записи `reports/reconciliation_<YYYY-MM-DD>.md` вернуть одной строкой:

`reconcile-meds: записан reports/reconciliation_<YYYY-MM-DD>.md. Активных препаратов: N. Противоречий: M. Consensus-сигналов: K. Открытых вопросов: L.`

Если найдены критические расхождения (одна и та же активная схема, разные дозы у двух специалистов) — дополнительная строка:

`🔴 Критическое расхождение: <МНН>: <spec A> = <доза A>, <spec B> = <доза B>. Срочно очно.`

## История

Команда введена 2026-05-10 как ответ на пункт BACKLOG «Проверка противоречий между специалистами» из Приоритета 2. Архитектурно встроена параллельно `commands/refresh-profile.md`:

- `refresh-profile` — обновляет вид специалиста на пациентку (вертикаль).
- `reconcile-meds` — сводит виды специалистов между собой (горизонталь).

Обе команды — утилитарные, без собственного контекста. Главный пользователь обеих — chief.
